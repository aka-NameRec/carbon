# In-process SSE broker для MVP

## Статус

Принято для MVP; обязательно пересмотреть после MVP.

## Контекст

SSE в Carbon служит только invalidation-каналом: после reconnect frontend полностью refetch-ит состояние. PostgreSQL и Markdown vault остаются источниками состояния, поэтому SSE не должен становиться очередью доставки или ещё одной проекцией данных.

## Решение

Backend использует in-process broker, который fan-out публикует события только текущим подключённым SSE-клиентам. События не сохраняются, не имеют replay и не передаются между процессами backend. Heartbeat поддерживает обнаружение разрыва соединения.

## Последствия и пересмотр после MVP

Решение корректно для одного backend process и локального MVP. При нескольких процессах, remote deployment, требованиях гарантированной доставки, durable replay или повышенной нагрузке оно станет недостаточным. После MVP нужно оценить внешний transport/broker и стратегию event persistence, не меняя vault/DB source-of-truth.
